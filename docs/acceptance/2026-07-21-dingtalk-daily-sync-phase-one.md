# 钉钉每日考勤同步一期

## 已实现边界

- 同步范围严格按 `HRMS DingTalk Settings.company` 隔离；迁移时将历史占位公司 `1` 修复为 `永新`。
- 钉钉部门、用户、考勤原始响应、用户映射及同步日志均具备公司字段。
- 手工同步一个日期时，数据先写入 `HRMS DingTalk Raw Record`，再生成 `HRMS Attendance Import Batch` 和可覆盖的 `HRMS Attendance Day Check` 草稿。
- 同一公司、同一日期的 API 草稿使用稳定批次校验码；重复执行会重建草稿而不会叠加记录。
- 未匹配 UserId/工号的记录会进入既有考勤异常队列，不能通过月度锁定进入薪资。
- 已锁定月份拒绝 API 草稿覆盖；薪资仍只读取已锁定的月度考勤版本。
- 定时任务每天 `02:30` 运行；默认关闭，启用后同步昨天并回补最近 7 天（可配置 1–31 天）。
- 审批流程编码由人事在设置中维护，格式为 `请假=流程编码`；同步的审批详情先保留为原始证据，后续字段映射不能绕过人事确认。

## 上线前配置

1. 部署代码并执行 `bench --site <site> migrate`、`bench build --app hrms`、清缓存和重启。
2. 以 HR Manager 或 System Manager 打开“设置中心 → 钉钉集成”。
3. 在 `HRMS DingTalk Settings` 中确认同步公司为 `永新`，填写企业内部应用的 Client ID / Client Secret。
4. 设置同步模式为“内网服务器主动拉取API”；先保持“启用钉钉集成”和“启用每日自动同步”关闭。
5. 在钉钉侧仅授予通讯录读取、考勤读取、审批读取权限；不授予考勤或通讯录写入权限。
6. 手工同步 5 名试点员工的单日数据，核对 UserId、工号、上下班时间、缺卡和异常结果。
7. 配置审批流程编码并核对请假、加班、补卡、外出、出差的原始审批记录。
8. 连续人工核对 3 天无差异后，才开启每日自动同步。

## 验收结果

- 数据库迁移成功；钉钉设置当前为公司 `永新`、同步关闭、回补天数 `7`、未保存 Client Secret。
- 定时任务在关闭状态返回 `skipped`，不会发起网络请求。
- `TEST-HRMS` 隔离验收使用模拟钉钉响应完成两次转换：两次均只保留 1 条 API 草稿，不产生重复；永新员工数及最后修改时间未变化。
