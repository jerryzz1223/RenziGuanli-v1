# 永新薪酬统算使用说明与项目企划

## 目标与边界

本项目将永新电子（常熟）有限公司现行的薪资异动、钉钉考勤、苹果树、福利扣款和工资结算表收敛为一条可复核的月度链路：

`员工与组织主数据 -> 薪资异动 -> 已锁定考勤终稿 -> 已确认月度变量 -> 薪资输入表 -> 薪资结算表 -> 复核确认 -> 发放/工资条`

系统不是把历史 Excel 直接显示在网页上。Excel/CSV 仅作为受控输入和历史核对依据；结算金额由已锁定的来源记录和系统公式生成。首个试用版不做实时钉钉 API、自动个税申报、银行代发或社保公积金基数自动计算。

每次试算必须传入三个范围键：`company`、`payroll_month`、`attendance_lock_version`。薪资 API 只读取同公司的已锁定月度考勤终稿；来源记录、输入表、结算表的查询、删除和幂等生成均以这三个键隔离。跨公司、未锁定考勤或不同锁定版本的结果必须阻断。

### 考勤锁定版本如何定义

锁定版本不是由薪资人员手工填写的编号，而是考勤模块对某公司某个月度终稿的不可变快照：日核对、异常确认、部门确认完成后首次锁定为 `V1`。若已锁定月份因更正被重开，考勤重新生成月度终稿时自动递增为 `V2`，再次锁定后成为新的当前版本。历史 `V1` 保留给审计和已生成工资核对；薪资页面右上角只会列出实际存在且状态为“已锁定”的版本，并默认选择当前版本。草稿、已重开但未再次锁定的考勤数据不会出现在薪资可选范围中。

薪资输入、变量、福利来源和结算的追溯键固定为：`公司 + 薪资月份 + 考勤锁定版本`。该范围一旦确认结算，系统不允许重新生成覆盖；若要处理考勤更正，应使用新锁定版本重新走完整闭环，而不是修改旧结算。

## 系统计算口径

结算公式与 `5.2人资考勤.xlsx` 的“薪资结算表”一致，全部结果保存为可追溯字段：

1. 薪资小计：`底薪 + 职能津贴 + 证书及多能工津贴`。
2. 缺勤扣款：`ROUND(薪资小计 / 174 * 调整后缺勤工时, 2)`。
3. 加班工资：平日 `ROUND(底薪 / 174 * 平日加班 * 1.5, 2)`；周末 `ROUND(底薪 / 174 * 调整后周末加班 * 2, 2)`；节假日 `ROUND(底薪 / 174 * 节假日加班 * 3, 2)`。
4. 夜班津贴：`大夜班次数 * 45 + 小夜班次数 * 24`。
5. 应付工资：`薪资小计 - 缺勤扣款 + 加班费小计 + 夜班津贴 + 奖金小计 - 惩处小计`。
6. 计税工资：`应付工资 - 社保个人 - 公积金个人 + 已发福利`。
7. 实发工资：`计税工资 - 所得税 - 年终奖所得税 - 水电费及扣款 + 继续服务奖 - 已发福利`。
8. 公司实际负担：`应付工资 + 社保公司 + 公积金公司 + 继续服务奖 + 已发福利`。

奖金/扣款来源包括：奖惩提报、证书多能工津贴、全勤奖、住房补贴、学历补贴、宿舍费、水电费、个人和公司社保公积金、提案改善奖、继续服务奖、苹果树、所得税、年终奖所得税、已发福利、生产奖、离职薪资结算。每一笔变量保存来源文件/工作表/单据、员工、公司、月份、锁定版本、来源 JSON 与来源哈希。

### 规则如何真正参与计算

规则中心中的“公式说明”是 Excel 口径和审计说明，**不会**以 Python、JavaScript 或 Excel 文本直接执行。薪资属于高风险金额计算，系统把规则分成三类：

| 规则类型 | 当前实现 | 可修改范围 | 对何时生效 |
| --- | --- | --- | --- |
| 参数化公式 | 全勤奖阶梯、缺勤/加班工时除数、平日/周末/节假日倍率、大/小夜班单价、公司社保区间、公司公积金承担方式 | `System Manager` 或 `HR Manager` 修改受校验的参数 JSON；保存时校验，试算前再次校验 | 下一次未确认的输入表/结算试算；参数快照写入来源追溯 |
| 固定计算器公式 | 薪资小计汇总、缺勤与周末工时调整、应付工资、计税工资、实发工资、公司成本汇总 | 通过受控代码发布调整，避免任意文本公式造成错误薪资或执行风险 | 下一次未确认试算；已确认结算不覆盖 |
| 来源/说明规则 | 租房资格、学历资格、宿舍签字、个税、社保名单、离职结算等 | 维护说明、来源和导入确认规则；金额由已确认来源记录导入 | 确认来源并同步变量后参与下一次试算 |

页面的“校验可执行规则”会显示每一个参数化规则的有效状态、来源及最终读取的参数。任何已启用规则缺参数、参数格式错误或不在生效区间，系统拒绝生成输入表和结算表。字段映射表中的 Excel 公式仅用于对照历史表列，实际金额由上述受控计算器生成。

## 页面使用方式

完整初始化步骤、页面关键词跳转和每一步验收条件见《薪酬配置中心操作指南》。

进入“薪酬管理中心”后，顶部只保留四个主入口：

1. **本月算薪**：默认页。选择公司、月份，系统自动加载可用的考勤锁定版本并默认当前版本；按六步检查本月是否可算。没有已锁定终稿时不会发起试算，须返回考勤模块完成锁定。
2. **员工薪资**：从员工花名册联动查看员工状态、部门、岗位、最近薪资异动和当前固定/总工资。进入“薪资主数据”导入薪资架构，维护员工薪资异动及其生效日期。
3. **薪酬项目与规则**：先点击“校验可执行规则”，再查看和维护薪资项目、公式说明、适用范围、来源资料、缺失规则说明及 Excel 字段映射。仅 `System Manager` 与 `HR Manager` 能修改受允许修改的规则或确认结算；`HR User` 仅查看。
4. **报表与发放**：查看部门汇总、成本分析、工资发放清单。该页仅应消费已确认的结算结果。

推荐的月度操作顺序：

1. 在考勤导入中心完成日核对、异常处理和月度终稿锁定，记录锁定版本。
2. 在员工薪资中确认本月生效的薪资异动。进入薪资的每位员工都必须有一条已批准异动。
3. 用统一“导入薪资资料”入口导入各类 Excel，或在福利扣款来源中心逐笔维护并确认。福利来源确认后执行“同步到薪资变量”。
4. 在“本月算薪”生成薪资输入表，核对员工数、标准工时、加班、苹果树、全勤、住房/学历、宿舍和社保扣款。
5. 生成薪资结算表。常规视图用于日常复核；点击“显示所有细项”可展开原表对应的完整字段和金额。
6. 完成差异复核后点击“确认本月结算”。确认会锁住该公司、月份和考勤锁定版本，禁止重新试算覆盖。

## 导入规范

推荐使用“数据闭环导入”的三张标准工作表：`员工薪资异动导入`、`月度考勤终稿导入`、`福利扣款来源导入`。系统提供字段模板和“薪资结算字段对应”预览。

完整历史“薪资结算表”可以导入进行字段核对，但不会直接覆盖系统结算结果；正式结算必须由薪资主数据、已锁定考勤和受控变量重新计算。导入时优先用工号匹配员工，姓名只作为辅助匹配；不匹配员工、跨公司员工、未锁定考勤和待确认来源必须处理后才能确认结算。

## 尚待人事/财务确认的规则

以下规则已在规则中心标记为“需要确认”，不能被当作自动化的正式依据：

- 社保与公积金的当月增减员、缴费基数、比例、上下限和公司承担比例。目前可从确认名单导入；公司社保缺失时才按历史结算表区间回推。
- 个税的累计预扣、专项附加扣除、年终奖计税方案。当前所得税与年终奖所得税必须由财务确认后作为月度变量导入。
- 离职当月薪资、未满月折算、住房补贴“满勤”的精确定义和结算截止日。
- 证书、多能工、职务津贴的资格有效期和失效日期。当前以薪资异动或确认变量为准。

## 验收标准

试点班组的一个月度可以验收为完成，当且仅当：

- 薪资输入表人数等于同范围的已锁定考勤终稿人数；每个员工均有有效薪资异动。
- 所有已确认福利/扣款来源都有员工、公司、月份、锁定版本和来源追溯信息。
- 薪资结算表人数等于输入表人数，且能展示全部历史 Excel 结算细项。
- 随机抽取至少三名员工，系统的薪资小计、加班费、夜班、缺勤扣款、应付、实发和公司成本可追溯并与审批/导入批次核对。
- 尝试使用另一公司或另一锁定版本生成/确认同月份工资时，系统拒绝跨范围读取或覆盖。
