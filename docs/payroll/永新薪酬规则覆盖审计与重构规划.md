# 永新薪酬规则覆盖审计与重构规划

## 结论

参考截图可以覆盖薪酬系统的配置框架，但不能单独覆盖永新的完整计薪规则。

可直接采用的框架包括：工资项、工资表模板、员工薪资分配、计薪规则、最低工资、企业设置、工资表、复核和操作记录。不能照搬的部分包括：永新的全勤阶梯、174 小时口径、缺勤与周末加班冲抵、夜班单价、学历/租房/宿舍资格、苹果树审批与签字、继续服务奖、离职特殊结算、历史社保回推及考勤锁定版本。

目标架构不是复制参考产品页面，而是复用 HRMS 标准薪资能力，并把永新规则作为公司级、版本化、可追溯的受控输入。

## 目标数据模型

### 标准 HRMS 层

1. `Salary Component`：工资项字典，只定义名称、应发/应扣、税务属性，不保存员工金额。
2. `Salary Structure`：工资表模板，组合一个员工类别或薪资组需要的工资项。
3. `Salary Structure Assignment`：员工在某生效日期使用哪套模板及基础金额。
4. `Payroll Entry`：已复核月度结果的正式工资表入口。
5. `Salary Slip`：正式工资单；在自定义结算稳定前不自动提交。

### 永新业务层

1. `HRMS Employee Salary Change`：入职定薪、转正、晋升、岗位调整和年度调薪的审批事实记录。
2. `HRMS Payroll Rule`：公司级规则和参数；同一公司内规则编码唯一，修改保留版本记录。
3. `HRMS Monthly Attendance Summary`：同公司、月份和锁定版本的考勤终稿快照。
4. `HRMS Payroll Welfare Source Record`：资格、申请、签字或财务确认来源。
5. `HRMS Payroll Variable Record`：来源确认后冻结的当月员工金额。
6. `HRMS Payroll Input Record`：考勤终稿和变量的计薪输入快照。
7. `HRMS Payroll Settlement Record`：逐项公式计算结果、来源快照和确认状态。

## 可执行规则边界

规则中心分三类，不能混用：

1. 参数化公式：全勤阶梯、标准小时除数、加班倍率、夜班单价、公司社保区间、公司公积金承担方式。只有经过白名单校验的 JSON 参数参与计算。
2. 固定计算器公式：薪资小计、缺勤/周末工时调整、应付、计税、实发和公司成本。结构变化必须通过代码评审和测试发布。
3. 来源/说明规则：学历、租房、宿舍、个税、高温补贴、继续服务奖、未满月折算、最低工资等。当前资料不足时只能展示缺失项，不得把自然语言直接执行为金额。

每次结算保存所有实际读取的规则参数、薪资异动、考勤终稿、变量记录名称与来源哈希。已确认结算不能因后续修改规则而变化。

## 已确认的永新公式

1. 薪资小计：`底薪 + 职能津贴 + 证书及多能工津贴`。
2. 调整后缺勤：`MAX(标准工时 - 实际出勤 - 调整前周末加班, 0)`，最终以锁定考勤终稿字段为准。
3. 缺勤扣款：`ROUND(薪资小计 / 174 * 调整后缺勤工时, 2)`。
4. 平日加班：`ROUND(底薪 / 174 * 平日加班时数 * 1.5, 2)`。
5. 周末加班：`ROUND(底薪 / 174 * 调整后周末加班时数 * 2, 2)`。
6. 节假日加班：`ROUND(底薪 / 174 * 节假日加班时数 * 3, 2)`。
7. 夜班津贴：`大夜班次数 * 45 + 小夜班次数 * 24`。
8. 应付、计税、实发和公司实际负担按历史薪资结算表逐项计算，每一项先保留两位小数再汇总。
9. 苹果树金额：`(绿苹果颗数 - 红苹果颗数) * 5`；只读取审批通过、员工确认并纳入考勤锁定版本的记录。
10. 试用期未满 7 天离职：符合 8 小时的工作日按 100 元/天，工作 1 天离职无薪；其余离职扣款必须经离职申请审批确认。

## 仍需确认的规则

下列规则不能从现有资料得到唯一、长期有效的自动计算方式：

- 入职、离职、转正和月中调薪的固定薪资分段折算口径。
- 事假、病假、工伤、婚丧假、产假等各假别最终影响工资的百分比；薪资只消费考勤锁定后的调整工时。
- 当年社保、公积金的缴费基数、比例、上下限和增减员月份。
- 累计预扣个税、专项附加扣除和年终奖计税方案。
- 继续服务奖每年度金额、发放月份和缺勤认定。
- 高温补贴年度单价、岗位范围和发放月份。
- 最低工资的工作地、比较口径、标准金额和生效区间。

这些项目必须先建立经人事/财务批准的规则版本或月度确认来源，不能由开发人员猜测数值。

## 页面重构

薪酬管理中心保留四个主入口：

1. 本月算薪：公司、月份、考勤锁定版本，按准备、试算、复核、确认四个阶段展示。
2. 员工薪资：员工定薪覆盖率、薪资异动审批、正式与测试数据提示。
3. 薪酬项目与规则：按“工资项 -> 工资表模板 -> 员工分配 -> 永新计薪规则 -> 薪资设置 -> 月工资表 -> 操作记录”顺序配置。
4. 报表与发放：只读取已确认结算，输出部门汇总、完整细项、差异检查和工资条。

日常页面默认只显示核心金额；“显示所有细项”展开历史 Excel 对应字段。规则页面同时展示公式说明、执行方式、执行参数、校验状态、来源资料和缺失规则说明，避免把文字描述误认为已执行公式。

## 实施阶段

### P0 已实施

- 薪资规则按公司隔离；查询、创建、修改和默认初始化均必须传公司。
- 输入表和结算表只读取同公司、同月份、同锁定版本数据。
- 变量来源从单条引用改为该员工全部来源记录。
- 加班、缺勤、奖金、应付、计税、实发和公司成本逐项取两位小数。
- 规则参数可在页面校验；自然语言公式不直接执行。
- 规则修改启用版本审计。

### P1 下一步

- 建立永新工资项字典和工资表模板。
- 批量把已批准员工薪资异动同步到 `Salary Structure Assignment`。
- 增加模板未分配、分配重叠、生效日期断档和测试薪资阻断。
- 建立薪资组，把部门/员工类别映射到模板和计薪规则。

### P2

- 完成学历、租房、宿舍、高温、继续服务奖的资格台账和月度冻结。
- 增加最低工资、环比、负数、超阈值、人数和来源缺失差异检查。
- 已确认结算转换为标准 `Payroll Entry` 和 `Salary Slip`，保留自定义来源追溯。

### P3

- 人事/财务确认未满月、社保公积金和个税规则后，再开发自动计算。
- 银行代发、个税申报和完整社保公积金自动化不属于当前阶段。

## 验收案例

1. A 公司规则参数变化不能影响 B 公司同月结算。
2. 未锁定或其他公司的考勤版本不能出现在薪资可选项中。
3. 同一员工多笔奖金/扣款均写入来源快照，删除或改动来源后旧结算仍可审计。
4. 平日、周末、节假日加班分别验证倍率与逐项取整。
5. 全勤奖覆盖 0、0.5、16、32、48 和大于 48 小时边界。
6. 员工没有已批准薪资异动、仍使用测试薪资或变量未匹配考勤时必须阻断。
7. 已确认结算不能被重新生成覆盖；考勤更正必须创建新锁定版本重新试算。
8. 展开全部细项后，薪资结算列与历史 Excel 字段一一对应且能查看来源。
