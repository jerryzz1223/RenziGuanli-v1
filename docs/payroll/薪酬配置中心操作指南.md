# 薪酬管理中心操作指南

本指南用于把员工定薪、考勤终稿、当月奖扣和计薪规则组合成可试算、可复核、可追溯的月度薪酬结果。页面不再把日常工作设计成必须逐个锁定的七步流程。

## 数据区域与按需入口

页面顶部显示六个数据区域，它们是状态入口，不是必须依次操作的步骤：

- 人员范围：只显示在职、正式、试用和待补资料人数。
- 员工定薪：维护有变动、缺失或待审批的定薪。
- 考勤数据：选择同公司、同月份的已锁定考勤终稿。
- 月度增减项：导入并确认奖金、补贴、扣款、社保和公积金等当月数据。
- 薪资试算：生成输入表和结算表，复核人数与金额。
- 确认与发放：使用已确认的结果生成报表、工资单和发放资料。

核算公式、工资表模板和考勤计薪参数属于“设置”，只在薪酬制度或公式变更时维护，日常算薪无需每月重复确认。

## 人员范围只看统计

“人员范围”不展示员工明细表，不在薪酬中心编辑花名册，也不要求每月点击确认。待补资料人数大于零时，从“打开员工花名册”进入人事主档处理。

## 试算时统一校验

使用者可按实际情况任意顺序处理数据。点击“生成薪资输入表”或“试算本月工资”时，系统实时检查：

1. 参与计算的员工是否有当月有效且已批准的定薪。
2. 薪资公式、字段映射和考勤计薪参数是否可执行。
3. 是否选择了当月已锁定考勤终稿，员工匹配是否唯一。
4. 奖金、补贴、扣款、社保公积金等来源是否已确认，是否能匹配考勤人员。

有阻断项时系统一次性列出需要处理的问题；没有阻断项时直接计算，不需要人工锁定前置步骤。

## 规则修改要求

- 仅 `System Manager` 与 `HR Manager` 可修改核算公式和考勤计薪参数。
- 规则修改后只影响之后重新试算的范围；已确认结算不可被覆盖。
- 考勤更正应产生新的锁定版本，新版本重新试算，历史结果保留。

## 最低验收案例

- 人员范围页只显示四个人数指标和状态提示，不显示员工明细表。
- 用户可从任意数据区域进入，不被“请先锁定上一步”阻断。
- 缺少定薪、规则、考勤或待确认月度来源时，试算会阻断并显示具体问题。
- 输入表人数、考勤终稿人数和结算表人数一致后才能确认结算。
- 已确认结算不能被重新生成覆盖。
