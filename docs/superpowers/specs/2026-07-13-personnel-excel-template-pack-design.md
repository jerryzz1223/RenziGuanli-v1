# 人事 Excel 模板包与复核提交设计

## 目标

将现有纸质人事表单转成可下载、可填写、可导入的 Excel 模板包。所有字段均为结构化字段，导入后必须经人事复核，复核通过并提交后才写入员工主档或提交标准 HRMS 单据。

首版覆盖：员工花名册、员工异动、转正/晋升/降级、合同续签、离职申请。员工主档仍以 `Employee` 为唯一事实源，工号 `custom_employee_code` 为跨模块稳定业务键；Frappe 内部 `Employee.name` 仅作内部主键，不在模板或人员界面作为编号展示。

## 模板包

下载一个工作簿 `人事业务导入模板包.xlsx`，其中包含以下 Sheet：

1. `填写说明`：字段说明、必填规则、枚举值、日期格式、复核提交规则。
2. `员工花名册`：以沟通表“花名册”字段为基线，覆盖工号、姓名、部门、入职日期、联系电话、身份证号码、户籍地址、籍贯、岗位、直间接、民族、婚姻状况、出生年月、年龄、性别、学历类别、学习形式、学历、毕业院校、科系、现居住地、交通工具、紧急联系人/电话、试用期、转正日期/是否转正、合同签订日/编号/次数/结束月、社保/医保/公积金。
3. `员工异动`：工号、异动类型、申请日期、生效日期、原公司/部门/岗位/职级、目标公司/部门/岗位/职级、异动原因、申请人、审批人、审批日期、审批意见、审批结果。
4. `转正晋降`：工号、业务类型（转正/晋升/降级）、申请日期、生效日期、原部门/岗位/职级、目标部门/岗位/职级、资格说明、培训完成情况、评估结果、申请人、审批人、审批日期、审批意见、审批结果。
5. `合同续签`：工号、合同类型、前次签订日、合同开始日、合同结束日、合同编号、签订次数、续签意愿、备注、申请人、审批人、审批日期、审批意见、审批结果。
6. `离职申请`：工号、离职原因、申请日期、拟离职日期、最后工作日、交接明细、资产/薪资/社保处理说明、申请人、审批人、审批日期、审批意见、审批结果。
7. `导入结果`：系统生成，列出 Sheet、Excel 行号、工号、动作、错误字段、错误信息、复核状态、生成单据。

所有业务 Sheet 首列均为工号。部门在业务展示、模板和导出中使用 `Department.department_name`，不暴露 Frappe Link 名称中的 `- 1D` 等技术后缀。

## 结构化审批与审计

每个业务行均保存以下审批字段：`申请人`、`审批人`、`审批日期`、`审批意见`、`审批结果`。不依赖扫描件或手写签名图片。

导入批次和行记录必须额外保存：上传文件、Sheet 名、Excel 行号、导入人、导入时间、校验结果、复核人、复核时间、复核结论、提交人、提交时间、目标单据类型和目标单据名称。任何提交失败均保留该行和错误信息，不能静默跳过或部分覆盖。

## 数据流与系统落点

### 花名册

1. 校验工号、姓名、部门、岗位、日期、枚举值与重复匹配。
2. 仅在复核通过后创建或更新 `Employee` 和已配置的 Employee Custom Field。
3. 部门、岗位、工作性质等基础资料按既有规则创建或匹配；部门仅匹配业务名称，不用技术后缀作为用户输入。
4. 身份证可校验并建议出生日期、年龄、性别，但不得无提示覆盖人工填写值。

### 员工异动

1. 以工号定位 Employee，比较原值与目标值。
2. 复核通过后创建 `Employee Transfer` 草稿；目标属性写入标准 `transfer_details`。
3. 仅在标准单据提交后由 HRMS 生成/更新 `Employee Property History` 与 Employee 任职属性。

### 转正、晋升、降级

1. 以工号定位 Employee，校验业务类型与生效日期。
2. 复核通过后创建 `Employee Promotion` 草稿；目标属性写入 `promotion_details`。
3. 资格、培训和评估结论保留在结构化导入行与目标单据的可扩展字段中；标准单据提交后更新任职历史。

### 合同续签

1. 以工号定位 Employee，校验合同日期、编号和次数。
2. 复核通过后建立结构化合同续签记录；提交后同步 Employee 已有合同摘要字段：合同编号、签订日期、签订次数、结束日期。
3. 不将合同续签误表示为岗位异动或直接替换历史审计信息。

### 离职申请

1. 以工号定位 Employee，校验申请日、拟离职日、最后工作日和交接明细。
2. 复核通过后创建 `Employee Separation` 草稿。
3. 仅在标准离职单据提交后执行 HRMS 的离职流程，不在导入时直接修改 Employee 状态。

## 状态机与权限

导入行状态：`待校验` -> `校验失败` 或 `待复核` -> `复核退回` 或 `复核通过` -> `已生成草稿` -> `已提交` / `提交失败`。

权限分层：

- 人事录入员：下载模板、上传、查看自身批次和校验错误，不可复核或提交。
- 人事复核员：复核行、填写复核结论、生成草稿。
- 人事管理员：提交标准 HRMS 单据、处理失败行、管理字段映射与模板版本。
- 其他角色：只读其被授权的 Employee/业务单据，不可下载含敏感字段的完整模板或导出。

现有 Employee 详情页的管理员编辑入口继续受 Frappe 权限控制；结构化业务变更优先通过标准异动、晋升、离职单据办理。

## 校验与错误处理

- 必填：每个 Sheet 的工号、业务关键日期和关键业务字段。
- 格式：日期、手机号、身份证、整数次数、布尔/枚举值。
- 关联：工号必须唯一且对应 Employee（花名册新建除外）；部门、岗位和公司必须可匹配或具备明确创建权限。
- 冲突：同一员工同一业务类型同一生效日的重复行必须阻断；已提交历史不得被覆盖。
- 业务规则：离职/异动/晋升生效日期不得早于入职日期；合同结束日不得早于开始日；身份证推导值与人工值冲突时标记待复核。
- 输出：每一个错误必须返回 Sheet、Excel 行号、字段名、原始值和可执行修复说明，并支持下载失败行。

## 验收标准

1. 模板包可下载，包含七个 Sheet 和字段说明；所有列名与字段中心配置一致。
2. 花名册导入可创建/更新测试公司 `TEST-HRMS` 员工，花名册显示工号和部门业务名称，不显示 Frappe 内部编号或 `- 1D` 后缀。
3. 异动、转正/晋降、离职导入复核后分别生成对应标准 Draft；提交后可在任职记录页追溯来源单据。
4. 合同续签导入复核后形成结构化记录并仅在提交时更新合同摘要。
5. 所有审批字段可在 Excel 导入、复核页和目标记录中查看与编辑。
6. 任一错误行均不写入 Employee 或提交标准单据；失败行可下载并保留审计信息。
7. 自动化测试使用 `Company=TEST-HRMS`、测试工号和来源字段隔离，不读写真实永新员工。

## 非目标

- 不做扫描件上传、OCR、电子签名或电子合同签署。
- 不改考勤、薪资、审批、组织架构模块的业务实现。
- 不批量修订真实永新历史数据；历史清洗必须另建受控迁移任务。
