# 排班表联动设计与验收

## 源表边界

来源为《排班表.xlsx》工作表 `V3.0 YXQD人资17 永新班别排配表`。第 6–20 行定义 15 个班别，包含基本时段、加班来源、取卡窗口、津贴条件和建议岗位。它没有员工公司工号和逐日排班日期，因此只能导入**班别定义**，不能据此给员工创建 Shift Assignment。源表里的“特别说明”属于审核依据，不可当作可执行公式。

## 联动链

1. 先上传文件并预览：按源行列出计算规则和系统 Shift Type 的新增、保留复核动作，以及治理规则的创建状态；结构错误阻止应用，语义矛盾作为待复核提示。
2. 应用时核对文件 SHA-256，保存 `HRMS Attendance Shift Rule` 的来源版本、文件、工作表、行号、校验值和原始行 JSON。规则编码在公司内稳定，重复导入按编码更新，不删除缺失行。
3. 经选择后生成并绑定系统 Shift Type。名称含公司标识和规则编码；已有 Shift Type 保留原值并标记复核，避免覆盖人工维护的自动考勤、宽限和时间设置。新建 Shift Type 默认不开启自动考勤。
4. 经选择后创建全公司 `HRMS Attendance Scheduling Policy`，保存来源关联。工作日、休息日、节假日、每日上限和一天多班可在导入前确认；首次默认待确认，人工检查完整治理字段后启用。再次导入仅更新来源关联，不覆盖已经人工配置的治理参数。
5. 班次分配使用已绑定的 Shift Type；排班工时校验优先读取同公司启用计算规则的基本工时，工作日另加固定免申请加班小时。对分段班次，Shift Type 只表示首段至末段的外部窗口，中间空档以及真实打卡取舍需单独复核。
6. 生效日期由导入者选择。规则更新不会直接改写已审核或锁定的历史考勤；历史月份仍走预览、核对、明确应用流程。

## 当前源表需复核

- 第 14 行：“生管仓库”是生管课内仓库人员使用的区分班次名称，津贴文字中的“生管课”表示人员范围，两者为已确认的合法对应，不作为冲突。
- 第 17 行：烧饭阿姨夜班是 `08:00–13:00`、`15:30–18:00` 两段基本时段；第 26 行特别说明写 `21:00–24:00`，而主表平日加班栏写 `21:30–24:00`，需确认 30 分钟差异。
- 第 19 行：CCD 白班休息栏原文 `12:00–12:00 扣 1H` 时段有误，数值列 `2.5H` 与备注 `3H` 冲突。已于 2026-09-23 确认系统口径为：`08:00–20:00`总休息 `1H`，计薪 `11H = 8H 基本 + 3H 平日加班`；源表原文仍保留供审计。
- 第 20 行：CCD 夜班确认沿用生产夜班的小夜班/大夜班津贴标准，说明中写“生产人员班”为合法共用口径，不作为冲突。

上述矛盾不会自动猜测修正。导入预览提示其中可结构化检测的差异，正式应用前由人事核实源表，并选择生效日及治理参数。

## 验收

- 静态及单元检查：解析 15 个班别、分段班次时间映射、已有 Shift Type 不被重写、页面字段、DocType 字段、排班合规工时校验。
- 本地站点检查：两张 DocType 表有新增字段，导入预览能显示动作与提示；确认后规则卡显示来源、系统班次和状态；实际 Shift Assignment 可选择新 Shift Type；治理规则启用后由服务端拦截超限排班。
- 真实数据检查：抽取生产白夜班、CCD 夜班、食堂分段班各一人一天；比较来源班别、打卡窗口、基本工时、加班、津贴与人工审核结果。锁定月份只预览，不自动重算。
