# 员工花名册与资料维护链路

## 唯一身份与主档

- 人资系统的 `Employee` 是员工资料主档。导入、钉钉映射和人工核对均使用“公司 + 公司工号（`custom_employee_code`）”识别员工。姓名、手机号、身份证号只能帮助人工核对，不能代替工号自动匹配。
- 目前 `Employee.name` 也使用公司工号，且 `EmployeeMaster` 对工号作全局唯一检查。因此跨公司复用相同工号尚不受支持；如确有这种业务场景，须先设计关联单据迁移，不能直接改工号。
- 已建档员工的工号不能通过普通导入改写。员工编号更正需单独迁移并核对所有关联单据。

## 每次维护的固定顺序

1. 确认操作公司和工号，先处理缺工号、重复工号、公司名称错误。不要用姓名或电话猜测身份。
2. 首次建在职档案时，先拉取钉钉全量在职资料，再执行“钉钉一次建档预检”。同步日志须已完成，接收数与本次档案记录数一致，工号完整且唯一；新建档案需要真实的姓名、入职日期、性别、出生日期及工作性质等关键事实。来源或系统标准值有缺口时先修正，再重新同步和预检。
3. 预检通过后，一次导入同一钉钉批次：系统没有的员工按工号新建；系统已有的员工仅补空字段，已有值差异保留逐字段人工核对。拉取钉钉资料本身是只读操作，不自动决定离职。其他扩展字段随后在员工档案内完善。
4. 后续待入职员工仍通过钉钉扫码入职审批进入主档。当前钉钉接口没有提供已离职历史档案的全量来源；原有历史离职档案保留在系统中维护，不能因其不在钉钉在职名单里就重建或清除。确需补建钉钉未覆盖的历史档案时，按公司工号使用花名册新增/修改入口并保留来源依据。
5. 单个员工的修正回到同一 `Employee` 档案。离职须有明确的工作性质和日期；不要把未出现在某个来源文件当作离职证明。
6. 导入后核对新增、更新、失败行，以及“系统在职但不在钉钉 / 系统离职但钉钉在职 / 钉钉在职但系统无档案”三组差异。组织花名册同步是从员工主档生成组织视图，不能作为第二套员工主档维护。

“完整花名册核对”会将表中遗漏的当前员工标记为离职，只能用于经过审核的完整名册。它现在要求可用的钉钉在职快照、工号完整且唯一，并阻断在职来源冲突。日常新增从钉钉入职同步进入，单人资料修改在员工档案中完成；Excel 新增/修改只用于钉钉未覆盖的历史补录或经审核的批量修正。

## 后续建设清单

1. 为每个员工字段定来源责任和修改权限，例如钉钉在职信息、人资人工档案、正式异动单据及系统计算值，并在比对页展示来源、时间和审核人。
2. 钉钉一次建档已绑定来源批次、待审记录和员工资料版本，写入前如有变化会要求重新预检。Excel 花名册入口仍需补齐同等级的预览版本锁定，避免确认后资料变化。
3. 对导入批次保存文件摘要、操作人、逐行结果和修改前后值，提供失败重试与回滚方案；在生产数据上验证现有导入记录是否满足审计要求。
4. 整理历史存量：按公司工号查空值、重复、钉钉映射冲突和跨公司重号；先生成只读差异清单，再逐条修正，避免批量猜测。
5. 在目标站点完成一次真实的钉钉全量同步、待入职审批、花名册预览/导入和员工详情核对。代码定向测试不代表线上资料已经重算或页面已经生效。
