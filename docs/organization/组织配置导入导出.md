# 组织配置导入导出

入口：部门 → 部门列表或组织架构图 → 顶部“组织配置” → 导出配置／导入配置。只有系统管理员可以操作整个公司的配置迁移。

## 迁移到服务器

1. 服务器先部署包含 `hrms.api.organization_package` 的系统版本，并更新缓存。持续自动更新还需要启用 Frappe 调度器和后台队列；新版本的 Employee hooks 和定时任务需随应用部署注册。
2. 在服务器导入花名册，确保工号、部门、岗位正确且相关基础资料存在。
3. 在已经整理好的本地系统选择“导出配置”，获得私有 `.xlsx` 文件。
4. 在服务器选择“导入配置”，选择目标公司并上传文件，点击“校验并预览”。
5. 核对新增／更新数量、上下级、职级和待确认事项。修正错误后重新上传。预览通过后点击“确认导入”。
6. 列表与树图读取同一份配置。勾选“导入后按花名册自动更新人员”时，后续花名册变动会更新自动节点；手工节点保留手工安排。

## 文件内容

| 工作表 | 用途 |
| --- | --- |
| 组织层级 | 每个节点一行；节点编号保持不变，上级节点编号决定上下级。上级为空表示选定公司的直属节点。关联部门使用部门名称，服务器按目标公司唯一匹配。 |
| 人员任职 | 节点编号、引用类型、工号、姓名、图中职务、负责人位置、仅展示代理。工号按文本填写，保留前导零。 |
| 职级定义 | 职级编码、名称、等级顺序、上级职级编码。等级顺序越小越高；不清楚的等级可留空。组织节点的“职级编码”引用这里。 |
| 说明 | 格式版本及填写规则；请保留表头和格式版本。 |

“上级节点编号”与“上级职级编码”含义不同：前者决定谁在谁下面，后者定义等级体系。例如某岗位填 M2，不会自动改变它所属的课或组。岗位名、课长／组长等称呼不足以确定具体汇报关系。

示例（仅说明格式，不代表永新的实际职级）：

| 职级编码 | 职级名称 | 等级顺序 | 上级职级编码 |
| --- | --- | --- | --- |
| M1 | 管理职级 | 1 | |
| M2 | 岗位职级 | 2 | M1 |

导入定义后，编辑组织节点时可选择“图中职级”；列表与树图显示该职级。这里不会修改员工档案的 Employee Grade。

## 人员与代理

- 只按工号匹配目标公司的在职员工，不使用姓名或来源服务器内部 ID 猜测身份。
- 工号不存在、重复、员工已离职或部门不一致时提示错误；修正文件或服务器花名册后再导入。
- 原表人员缺少工号时可以保留姓名注释，显示待确认，不计入实际人数，也不会按同名自动绑定。
- 引用类型“代理人”保留代理身份；原表人员的负责人位置可以填 `primary` 或 `proxy`。已经确认的跨部门代理可标记“仅展示代理”。
- 自动普通岗位按部门和岗位分配；原表组线按已经绑定的工号更新。花名册只有部门和职位时，无法判断同名生产组、IPQC 组的具体归属，需要先导入或手工定义。
- “合并关联部门”每行一个部门名称，使独立花名册部门进入图中已经确认的分组，避免重复建根节点。

## 更新规则

- 相同节点编号更新原节点，缺少的编号新增；文件未包含的节点保留。不要为了改名称而改节点编号。
- 不删除或覆盖 Employee、Department、Designation 或 Employee Grade 基础资料。
- 导入前生成私有配置备份，并保留 Frappe 节点修改记录。备份用于恢复对应节点的配置；因为导入采用合并模式，恢复备份不会自动删除后来新增的节点。
- 节点循环、职级循环、缺少上级、重复部门节点、重复自动岗位、无效字段、文件公式均在导入前校验。
- 预览后花名册或组织已变化，需要重新预览；防止用旧预览覆盖新数据。
- 文件及备份包含人员信息，均保存为私有附件。

## 导出树状架构图

入口：组织架构图 → 顶部“导出架构图”。

- **完整架构**：导出当前公司整棵展示树，包含折叠的全部下级和卡片人员；忽略页面缩放、滚动、搜索与局部查看范围。
- **当前展开层级**：保留当前查看范围、搜索结果与展开状态，收起的下级不进入图片。
- **SVG 矢量图**：建议用于完整架构，可在浏览器打开、放大查看和打印。包含独立文字、卡片和连线，不依赖系统页面样式。
- **PNG 图片**：便于分享；整图等比缩放到最长边 8192 像素、最多 1600 万像素以内，大图查看细节建议使用 SVG。

导出使用当前已加载的组织数据，保留代理、正式与待确认等卡片标记，不改变任职、人数或展开状态。文件通过浏览器下载。图片用于查看；服务器迁移仍使用“组织配置”导出的 XLSX 文件。
