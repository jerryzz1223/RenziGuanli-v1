# 组织架构自动读取花名册

本地永新公司已启用持续同步。以 Employee.name（工号对应的稳定档案编号）识别人，以花名册部门、职位、在职状态确定自动岗位成员。重复运行不重复建节点，不反写 Employee。

## 触发方式

- 员工保存或删除后，事务提交成功才投递后台任务；回滚的员工变更不会同步。
- 每 5 分钟检查一次，补获直接数据库导入等未触发文档事件的变化。
- 打开或重新加载组织列表、架构图时检查最新数据。后台更新完成后，已打开页面会接收更新通知。
- 部门权限受限的账号只触发后台同步，不能用其局部可见花名册覆盖全公司数据。

## 自动更新范围

自动补建已启用部门对应的课、室、组、线，以及花名册中的岗位；员工新增、调部门、调职位、离职时更新自动岗位成员。空岗位保留，人数变为零。现有组织名称、上下级、编制保持用户设置。

尚未配置原表任职的课长、组长、线长及对应的“（代）”职位，只有唯一匹配才自动选为任职人或代理人；多人候选进入待确认。花名册没有的分管、生产组关系不会自动推断。

## 原表组线与完整人员

本地已用 `组织架构图260626.xlsx / 26Q3组织架构图` 补入 97 个组、线和人员栏。同名生产组、IPQC 以来源单元格区分。连接关系按原表核对，保养组归连续课，工程课助理直接归工程课，FQC 归进出货组。新增的部门内分组通过 `roster_subset` 关联所属课室，不创建虚假 Department。

原表姓名首次仅在同部门在职花名册中唯一匹配时绑定 Employee ID；之后按该 ID 跟随改名、调部门及离职。原表明确的跨部门代理是单独的展示引用，不改变部门归属或人数。原表未匹配姓名明确标记，不计入实际人数。原表任职保留当地职务名称，例如穆敏敏在图中为课长，花名册职位仍为副理；花名册中的（代）继续显示。

源图分组人员优先于普通自动职位桶，新员工没有组线依据时仍进入本部门的职位桶，可随后手动安排。自动职位桶被原表分组完全接管且人数为零时，从视图隐藏，数据库记录保留。手动节点和有编制的空岗位继续显示。

层级列表与树图共用这些节点。卡片显示全部人员；点击课室聚焦并展开完整分支，组织路径可返回上级。一览全局允许缩小，普通阅读保留可读比例。原表空缺数字单独标记；实际人数和当前空缺按在职花名册、已设置编制计算。

`scripts/restore_organization_template.py` 默认预览，`--apply` 在私有目录备份后写入。重复运行按来源单元格去重，保留已编辑节点。已确认的分管不变；原表补齐陈文萍、逯瑜、杨玉婷的原待分管部门。原表不进入周期重复覆盖，周期任务只更新已建立的人员绑定。

编辑节点的“人员随花名册自动更新”控制任职配置。关闭后保留手动人员，不重新覆盖；手动岗位存在未分配人员或任职与花名册冲突时会列出待完善项。手动指定人员优先于默认自动岗位，避免再次自动分配。

缺部门、缺职位、无法确定组织类型时列出待完善项；补齐源数据后可自动接入。公司页面显示缺部门人员，其他异常也在公司层级下列出。

## 配置与部署

站点配置 `organization_roster_auto_sync_companies` 为公司名称数组；本地值为 `["永新"]`。未列出的公司不启用自动同步。

代码入口为 `hrms.api.organization_roster_sync`。部署需更新应用代码、站点配置和 Scheduled Job Type；hooks 中的 5 分钟任务为 `scheduled_sync`。后台 worker、scheduler 必须运行。只更新此定时任务即可，无需修改其他任务的开关。

首次接管原有初次分配节点时，只自动接管仍与花名册一致的岗位；其他自定义节点保持手动。同步以组织版本行锁串行执行，手动保存也使用同一版本锁。

## 验证

`tests/manual_organization_auto_sync_runtime_check.py` 在事务中验证新增员工／部门／职位、调岗、离职、重新入职、手动覆盖、缺失字段及重复运行，结束后全部回滚。前端行为测试覆盖人员多选初始化、层级路径和过期响应隔离。
